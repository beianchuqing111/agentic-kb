# `eval/` —— 检索质量评估设施

这份 README **刻意放在 `corpus/` 的上一级**,而不是里面。

原因很具体:`ingest.loader.discover()`(`ingest/loader.py:299-307`)只跳过
`~$` 和 `.` 开头的文件,**不跳过 `README.md`**。把它放进 `corpus/seed/`,
如果目录里同时有非 md 的可入库文档,而扩展名又恰好在 `SUPPORTED_EXTS` 里,
它就会被当成语料导进去 —— 一篇讲评估设施怎么用的文档混进被测语料,
既是干扰项又是自指。放上一级零成本,不用改 loader 的语义。

## 这一套和 `scripts/check_*.py` 的分工

| | `check_*.py` | 本目录 |
|---|---|---|
| 回答的问题 | 流程**对不对** | 召回质量**好不好** |
| 判断依据 | 断言全绿 | 指标数字 |
| 花不花钱 | 不花 | `eval_gen` **花**,`eval_run` 不花 |
| 数据 | 一次性,跑完全清理 | 持久 collection,显式 `--purge` 才清 |

两者不重叠:**自检全绿的检索器完全可能召回得很难看**。

## 种子语料为什么长这样

**每篇 ≥1200 字符是硬要求,不是风格偏好。** `chunk_size=512` 下,
不到这个长度每篇只分出一块,`chunk_index` 恒等于 0,
整套「块级锚点」方案就等于没测 —— 而块级锚点正是本设施的核心。
这条坑 `scripts/check_ingest.py:42-45` 已经记过一次。
`check_eval.py` 会断言种子问答对的 `max(chunk_index) >= 2`。

**每篇的 `#0` 块只有标题(10~15 字)。** 这是现有分块器的真实行为:H1 在
第一个 `##` 之前自成一块。**故意保留**——评估要测的是真实系统的行为,
不是理想化之后的行为。它同时带来一个副作用:每篇的 `chunk_index` 至少到 6,
锚点方案天然被检验到。但它也意味着库里有一批近乎无用的极短块,
可能挤占召回窗口,这本身就是值得观测的现象。

**同领域、共享词汇。** 9 篇全是电网运维,否则没有干扰项,一篇语料人人 hit@1。
刻意制造的词汇重叠(都是真实业务里就会重叠的词,不是硬塞的):

| 词 | 出现处 | 用途 |
|---|---|---|
| 七十五摄氏度 | `02#1`(本体油温加强监视) `09#2`(迎峰度夏油温) | 词法检索的诱饵 |
| 百分之七 | `05#2`(断股补修) `06#2`(严重缺陷判定) | **真实的歧义题**:两处都算对 |
| 保存期限不少于三年 | `03#5` `04#5` `05#5` `06#5` `07#5` `08#3` | **六处都算对**,考排序而非召回 |
| 十开尔文 | `05#2` `07#3` `09#3` | 同阈值三种表述 |
| 百分之八十 | `05#2` `07#3` `09#2` | 相对温差 vs 负载率的同形数字 |
| 油温 | `02` `03` `09` | 跨文档词法诱饵 |
| 红外测温 | `01` `04` `05` `07` `09` | 跨文档语义诱饵 |

**`07_红外测温作业指导书.md` 的第四节是代词密集段**:整节用「上述参数」
「该系统」「该方法」「上述判据」「上述做法」指代本文档前几节,
单独看这一块几乎读不出说的是什么。它是 `CONTEXTUAL_ENABLED` 的直接考场 ——
定位语开着时,块前面会拼上文档摘要与章节名,这一节才可检索。

**`07#2` 是一张参数表**(发射率取值)。markdown 表格是一个段落,
`chunk_text` 不会在表格内部切开,所以它落在同一块里,可以出精确数值题。

**没有的实体是刻意的**,用来出可信的反例(已逐词核对库里出现 0 次):
断路器、六氟化硫 / SF6、GIS、蓄电池、互感器、电力电缆、欧姆。
反例必须「拿语料里真实的实体,配语料里不存在的取值」才可信 ——
「今天天气怎么样」这种对着电网语料一望即分,无论检索多烂都满分,等于没测。
注意**避雷器出现过 1 次**(`07#1`),拿它出反例会标错,别用。

## 用法

```bat
REM 花钱的:出题(默认 --dry-run 只打印计划,不调用)
scripts\eval_gen.py --corpus eval\corpus\seed --out eval\qa\seed.draft.jsonl --dry-run
scripts\eval_gen.py --corpus eval\corpus\seed --out eval\qa\seed.draft.jsonl --yes

REM 人工筛:把 draft 里好的行复制进 seed.jsonl,改 status/type/grade
REM 不花钱的:打分
scripts\eval_run.py --save-baseline after
scripts\eval_run.py --baseline after
```

改语料 / 问答集的纪律见项目根 `README.md` 的评估小节:
**k 有天花板**、**头条数字用阈值中性配置**、**反例单独成族**、
**基线比对拒绝跨不可比来源**。
